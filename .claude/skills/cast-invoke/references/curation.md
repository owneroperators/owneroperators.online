# Curate, don't polish (load-bearing doctrine)

From PLAN.md "Push the tools until they break":

- **Glitch is material.** Lopsided ASCII, a weird indent, a phrase that
  doesn't quite parse — the default move is **keep and curate**, not
  discard-and-retry-until-smooth. Repeat a typo three times with intention
  and it's a hook.
- **Don't scrub fingerprints.** Over-editing toward a neutral "professional"
  aesthetic is the failure mode to watch for. The site is not trying to look
  good; it's trying to look honest and slightly wrong, like a flyer
  photocopied one too many times.
- **"The models aren't good enough for this" is almost always the wrong
  conclusion.** The right question: _what did they give me that I can use,
  curate, or repeat with intention?_ If output is genuinely low-effort,
  push the tool first — reprompt, pipe through another cast member, combine
  outputs — before blaming it.

## Practical curation moves

- Run the same prompt 2–3 times and pick the take with the best accident —
  don't average them into mush.
- A roast from Jester is itself material: curate the roast, don't apply it
  verbatim.
- When Margot's ASCII is lopsided, ask whether the lopsidedness reads as
  intentional at a glance. If yes, keep it. If it reads as rendering error
  (broken box-drawing, orphan character), trim just that.

## The limits (same three, always)

1. Build must pass (`hugo` output, not vibes).
2. Canon beats glitch (`canon-voice` hard guardrails).
3. Fingerprints on-page yes, names no.
